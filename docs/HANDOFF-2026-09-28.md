## 1. Project overview

- **Name:** Egypt Roamer. Production: https://egyptroamer.com (GoDaddy Managed WordPress).
- **Business model: affiliate only.** The site discovers, explains and compares Egypt travel options, then hands the visitor to a partner through a tracked `/go/{offer}/` redirect. The partner handles availability, booking, payment and cancellation. Egypt Roamer takes **no bookings and no payments**. See `docs/ARCHITECTURE.md` [repo].
- **Brand and design:** the approved static prototype in `Egypt Roamer/` is the design reference. It is **never deployed or edited**.
  - Design tokens: Playfair Display × Inter; colours #C9A227, #101820, #FFFFFF. These are unchanged from the reference [doc: FINAL-PRELAUNCH-AUDIT §J–K].
  - No redesign, and don't touch the approved CSS. WordPress-only CSS goes in `assets/css/pages.css` [repo: CLAUDE.md].
- **Architectural boundaries** [repo: ARCHITECTURE.md]:
  - **Core** (`wordpress/wp-content/plugins/egypt-roamer-core/`) owns the business logic.
  - **Theme** (`wordpress/wp-content/themes/egypt-roamer/`) is presentation only. It reads data only through Core's template API, and no template contains an affiliate URL.
- **Never add, unless the owner explicitly asks:** WooCommerce, cart, checkout, direct booking, internal reservations, payment processing, customer accounts or availability data.
- **Plugins:** at most one SEO plugin. No extra cache plugins [repo: CLAUDE.md].

### How deploys work now (`.github/workflows/deploy-production.yml`, runbook `docs/DEPLOY.md`)

- **Trigger:** only a push to `main` that changes `wordpress/wp-content/themes/egypt-roamer/**` or `wordpress/wp-content/plugins/egypt-roamer-core/**`.
  - No `workflow_dispatch`. Workflow, docs or tools changes alone don't deploy.
  - Also set: `environment: production`, concurrency group `production-deploy` (no cancel), `permissions: contents: read`.
- **Test job:** PHP 8.1 and 8.3 lint; theme and Core version header = constant; `seed.json` valid; `tools/editorial.py check`; the theme JS bundles match `src/js`. The deploy job needs every test to pass.
- **Deploy job steps:**
  1. Stage the theme (without `src/`) and Core. The step refuses WordPress core files, `wp-config.php`, `.htaccess`, uploads, `.sql`/`.sqlite`/`.db`/`.wpress` files and symlinks.
  2. Read the expected versions.
  3. Check the secrets are present and that the user isn't a `git_deployer_*` account; pin the host key.
  4. Read-only preflight: login with retries; `~/html` is the WordPress root; both targets are real, writable folders inside `~/html/wp-content`; `wp core is-installed`.
  5. rsync Core, then the theme (safety boundaries in section 13).
  6. Read-only server health check: versions on disk and via WP-CLI, WordPress loads, active theme, Core active, `blog_public` = 0.
  7. Public health check: HTTP 200 without a PHP error for `/`, `/ar/`, `/destinations/`, Cairo EN and AR, `/experiences/`, `/journal/`. A stale version in the public pages is a warning only.
- **Production deploys cover theme and Core code only.** No database or content operations. **No automatic rollback.** To undo, revert the commit and push.
- The GoDaddy deployer action (`godaddy-wordpress/gd-wordpress-deployer`) is **no longer used**.

## 7. Editorial import and seed status

WP-CLI commands [repo: `includes/cli.php`]: `seed`, `editorial`, `languages`, `health`.
- **`wp egypt-roamer seed`:** creates the content model from `data/seed.json`. Re-runs **never overwrite** editors' titles, bodies, status or filled fields (`5f142e7`). The trust/legal pages are seeded as drafts containing only editorial notes, never auto-published [doc].
- **`wp egypt-roamer editorial --dry-run` / `wp egypt-roamer editorial`:**
  - Fills English bodies and excerpts from Core's `data/editorial/en/`.
  - Writes a field **only while it is empty or still exactly the one-line seed text**.
  - Never touches editor-changed text, translations, post status or "Ready to index".
  - Links guides to their destination. Guides stay drafts.
  - Outputs counts: bodies, excerpts, destination links, editor bodies kept, missing.
- **What actually ran on production:** the English editorial bodies are live on all 7 destinations and the checked experiences [prod]. So `wp egypt-roamer editorial` was run on production after Run #5.
  - The exact dry-run and import output (counts) is **not recorded in the repository**.
  - Non-English content was intentionally not changed.
- **Rules:**
  - Seed and editorial are **never** run automatically by a deploy.
  - Run them only when the owner explicitly asks, **`--dry-run` first**, show the result, then run for real.
  - Production commands run from `~/html` (running `wp` from `~` fails).

## 13. Safety rules (current)

A normal code deploy must:
- touch **only** `~/html/wp-content/themes/egypt-roamer` and `~/html/wp-content/plugins/egypt-roamer-core`;
- never deploy the repository root;
- never write to or delete from `~/html` or `~/html/wp-content` themselves, other themes or plugins, `uploads/`, `wp-admin/`, `wp-includes/`, `wp-config.php` or `.htaccess`;
- never run seed, editorial, migrations, translations, image imports, cache or database cleanup, or any database write;
- use deletion only inside each target folder:
  - the destination must be exactly one of the two paths (the workflow refuses anything else);
  - `--delete-after` scoped to that folder, `--max-delete=30`, no `--delete-excluded`;
  - a dry run first; an empty source is refused;
- never expose secrets or print environment dumps, `wp-config.php` or database credentials;
- never make unrelated server, DNS, billing or GoDaddy account changes;
- never claim a rollback happened. None is implemented: to undo, revert the commit and push.

Also:
- Keep "Discourage search engines" ticked until the launch gate passes.
- Don't invent content, translations, prices, hours, travel times, ratings, reviews, photos, statistics or affiliate providers/URLs.
- Files use LF line endings.
- Bump the Core version on each Core release.
